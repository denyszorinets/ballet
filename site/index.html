Orchestration for AI coding agents

Plan in the evening. Merge in the morning.

Ballet runs coding agents through the process a good team follows. You plan with a planner agent and approve the plan; separate agent sessions implement, review, verify and merge it ticket by ticket, in dependency order, while you sleep. You are asked only what agents can't decide safely.

How it works

You set direction. Agents do the work.

Humans are present for planning and for the questions that matter. Everything in between is a pipeline that runs on its own and explains itself.

Plan with the planner

Describe what you want. The planner reads your tickets and knowledge base and proposes epics and tickets with acceptance criteria and dependencies, as a changeset. Nothing changes until you approve it, in whole or in part.

Agents run the pipeline

Ready tickets start in dependency order, in parallel. Each stage is a fresh session on an agent built from your devcontainer, on the ticket's branch, with your skills. Watch any session live, and message or interrupt it.

Answer what only you can

The planner answers from the knowledge base when it can. The rest lands in one inbox. Answer within minutes and it goes into the running session; answer in the morning and the session resumes where it parked.

Read the digest

What was done, merged and failed, what waits and why, and what it cost in tokens. Then confirm or reject the assumptions agents made.

Why Ballet

An orchestrator of process, not another agent.

Agents are capable implementers now. What they lack is context and coordination. Ballet supplies both, and keeps the guarantees a team relies on.

Plans, not prompts

Work starts from a plan you approved: tickets with acceptance criteria and a dependency graph. Ballet runs whatever can run in parallel and holds work at the sync points.

Most agents start from a single issue or prompt.

No agent grades its own work

Implement, review, verify and integrate are separate sessions in fresh workspaces. They share artifacts and reports, never transcripts, so a reviewer sees what's really there.

Elsewhere, review is usually left to you.

Questions without babysitting

Agents ask only what's risky. Answer online and the session continues with its whole context; answer later and it resumes from where it parked. Every answer becomes a recorded decision.

No terminal to watch, no stalled night.

Knowledge that grows

A ticket isn't done until docs are updated, decisions recorded and debt filed in the organization's knowledge base. Every new session starts from that onboarding bundle, not from zero.

Projects get easier over time, not harder.

Your agents, your infrastructure

Self-hosted, with Claude Code or opencode per stage. Sessions run on a fleet of agents built from each project's devcontainer: a laptop, VMs or N containers on Kubernetes. No Docker socket needed.

No vendor sandbox, no lock-in to one agent.

Safe to leave alone

Token budgets per ticket, project and organization, enforced at Ballet's LLM gateway. Pause and kill switches, retries, stuck detection, durable state and a morning digest.

It stops before it overspends, and it explains itself.

The default pipeline

Four sessions, one ticket.

Every project configures its own stages, skills, models and gates; this is the template it starts from. Your process (TDD, docs, GitFlow) comes from your skills, not from Ballet.

Honestly

Is Ballet for you?

A good fit if you…

  • hand off whole tickets, not pair on lines of code;
  • want reviews, tests and docs enforced, not hoped for;
  • host several organizations or teams on one platform and must keep them apart;
  • want agents on your infrastructure, with your keys and limits.

Look elsewhere if you…

  • want an agent in your editor: use Claude Code, Cursor or Copilot directly;
  • want zero setup: a hosted agent starts faster;
  • need a runtime other than Claude Code or opencode, or pull-request automation beyond GitHub, today.
